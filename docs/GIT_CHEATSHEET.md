# GIT CHEATSHEET — шпаргалка для GitHub Desktop

> Все действия — в **GitHub Desktop** (не командная строка).
> Главное правило: **коммитить каждый раз, когда что-то заработало.**

---

## 🟢 Базовые действия

| Что хочу сделать | Где нажать |
|------------------|------------|
| **Посмотреть, что изменилось** | Вкладка `Changes` (слева) |
| **Сохранить текущее состояние (коммит)** | Вкладка `Changes` → написать сообщение в `Summary` → кнопка `Commit to main` |
| **Посмотреть всю историю** | Вкладка `History` (слева) |
| **Посмотреть, что было в конкретном коммите** | `History` → клик на коммит |

---

## ⬅️ Откат (главное)

| Ситуация | Что делать |
|----------|------------|
| **Изменения есть, но НЕ закоммичены — выбросить всё** | `Changes` → правый клик в списке файлов → `Discard all changes` |
| **Выбросить изменения только в одном файле** | `Changes` → правый клик на файле → `Discard changes` |
| **Отменить последний коммит (один шаг назад)** | `History` → правый клик на самом верхнем коммите → `Revert this commit` |
| **Отменить коммит, который был 2-3 шага назад** | `History` → правый клик на нужном коммите → `Revert this commit` |
| **Отменить несколько коммитов подряд** | Сделать `Revert` для каждого по очереди, начиная с самого свежего |

> ⚠️ **Revert** не удаляет коммит, а создаёт новый коммит, который отменяет старый.
> Это правильно — история честная, всегда видно, что было.

---

## 🔍 Посмотреть прошлое, ничего не меняя

| Что хочу | Где нажать |
|----------|------------|
| **Увидеть, какие файлы были в прошлом коммите** | `History` → клик на коммит (просто просмотр, ничего не меняется) |
| **Увидеть содержимое файла на момент коммита** | `History` → клик на коммит → клик на файл справа |

---

## 🌿 Ветки (для экспериментов)

Ветка = параллельная копия проекта, чтобы пробовать рискованное без страха сломать рабочее.

| Что хочу | Где нажать |
|----------|------------|
| **Создать ветку для эксперимента** | Кнопка `Current branch: main` (вверху) → `New Branch` → дать имя (например, `try-new-editor`) |
| **Переключиться обратно на main** | Кнопка `Current branch` → выбрать `main` |
| **Слить успешный эксперимент в main** | Переключиться на `main` → меню `Branch` → `Merge into current branch` → выбрать ветку эксперимента |
| **Выбросить неудачный эксперимент** | Переключиться на `main` (ветка с экспериментом просто останется, не мешает) |

---

## 📝 Формат сообщений коммитов

**Хорошо:**
- `Phase 1a: manifest.json, расширение загружается`
- `Phase 2c: bounds отправляются в service-worker`
- `Phase 4b: PDF экспорт работает на A4`
- `Bugfix: overlay не убирался на Notion`

**Плохо:** `fix`, `update`, `работает`, `1`

**Шаблон:** `[Фаза или Bugfix]: что именно сделано`

## 🔄 Типичный рабочий цикл

```
1. Дал задачу агенту
2. Агент сделал
3. Посмотрел Changes — список файлов разумный (не 30 штук)? ✓
4. Перезагрузил расширение в chrome://extensions
5. Прошёл чек-лист руками
6.
   ├── РАБОТАЕТ → Commit с осмысленным сообщением → следующая задача
   └── НЕ РАБОТАЕТ
       ├── мелкая проблема → попросил агента починить (1-2 попытки)
       └── серьёзная / 3-я попытка → Discard all changes → новая сессия
```

## 🆘 Сценарии "что делать если"

### Агент сломал, но я ещё не коммитил
→ `Changes` → правый клик → `Discard all changes`
→ Вернулся к последнему рабочему коммиту.

### Закоммитил, через секунду понял — сломано
→ `History` → правый клик на верхнем коммите → `Revert this commit`

### Закоммитил несколько штук, сломалось — не знаю где
→ Способ 1 (точный): Revert каждого по одному с конца, после каждого проверять.
→ Способ 2 (быстрый): Revert всех проблемных, переделать задачу заново.

### Хочу попробовать рискованное
→ Создать новую ветку **до** того, как начать. Если получится — Merge. Если нет — переключиться на main, ветку забыть.

### Кажется, что потерял рабочую версию
→ Открыть `History`. Прокрутить вниз. Найти коммит, где было хорошо. Он там. Revert всё, что после него.

### Совсем запутался, всё плохо
→ Не вводить никаких команд наугад. Описать ситуацию в чате — получить пошаговую инструкцию.

## ❌ Чего НЕ делать

- ❌ Не коммитить сломанный код ("потом починю").
- ❌ Не откладывать коммиты ("сделаю ещё чуть, потом закоммичу всё").
- ❌ Не использовать `Reset hard` без понимания (удаляет коммиты навсегда, в отличие от Revert).
- ❌ Не править файлы вручную в обход агента.
- ❌ Не игнорировать вкладку `Changes` перед коммитом (5 секунд просмотра спасают часы).
- ❌ Не вводить git-команды из интернета в терминал.

## 📏 Размер коммита — как понять

| Признак | Хорошо | Тревожно |
|---------|--------|----------|
| Изменённых файлов | 1-5 | 20+ |
| Тематика | Одна фича / один баг | Всё подряд |
| Описание одной фразой | Получается | Не получается |
| Можно проверить руками | Да, за 30 секунд | Нет |

Если тревожно — не коммитьте всё одним коммитом. Разбейте задачу на части, попросив агента сделать поэтапно.
